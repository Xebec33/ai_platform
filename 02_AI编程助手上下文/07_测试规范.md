# 测试规则

## 1. 测试目标

测试不仅用于发现 Bug，还用于验证系统架构是否按照预期工作。

核心原则：

> 每增加一个核心能力，都必须增加对应测试。

---

## 2. 测试层次

项目采用五层测试：

```text
Unit Test
↓
Integration Test
↓
Workflow Test
↓
E2E Test
↓
Self-Development E2E
```

---

## 3. Unit Test

测试独立模块：

```text
DSL Validator
Condition Evaluator
Loop Decision
State Manager
Node
Agent Executor
Tool
```

例如：

```text
maxIterations = 5
iteration = 5
stopCondition = false
```

必须得到：

```text
STOP
```

---

## 4. DSL Test

必须测试：

### Valid

```text
Start → Agent → End
```

### Invalid

* 缺少 Start；
* 缺少 End；
* 重复 Node ID；
* Edge 指向不存在 Node；
* 非法 Node Type；
* Agent 缺少配置；
* Loop 缺少 maxIterations；
* Condition 缺少 expression。

---

## 5. Runtime Test

至少测试：

```text
Start → Agent → End
```

然后逐渐增加：

```text
Condition
Parallel
Loop
```

---

## 6. Condition Test

例如：

```text
score >= 80
```

分别测试：

```text
score = 90 → true
score = 70 → false
```

还需要测试：

* undefined；
* 类型错误；
* 非法表达式。

---

## 7. Parallel Test

测试：

```text
A
B
C
```

是否能够正确并行执行并在 Merge 前等待所有任务。

还要测试：

* 一个分支失败；
* 超时；
* 部分结果；
* cancellation。

---

# Loop Test

## 8. First Failure → Second Success

必须测试：

```text
Iteration 1
→ Test Failed

Iteration 2
→ Test Passed

→ SUCCESS
```

这是最重要的 Loop Test。

---

## 9. Always Failure

```text
Iteration 1 → Failed
Iteration 2 → Failed
Iteration 3 → Failed
Iteration 4 → Failed
Iteration 5 → Failed
```

最终：

```text
FAILED
```

不能：

```text
Iteration 6
```

---

## 10. Retry

测试：

```text
API Error
 ↓
Retry
 ↓
Success
```

以及：

```text
API Error
 ↓
Retry
 ↓
Retry
 ↓
Failed
```

---

## 11. Timeout

必须测试：

```text
Node Timeout
```

以及：

```text
Workflow Timeout
```

确认不会导致 Worker 永久占用。

---

## 12. Cancellation

测试：

```text
RUNNING
 ↓
Cancel
 ↓
CANCELLED
```

取消后不能继续执行新的 Node。

---

## 13. Persistence Test

测试：

```text
Create Workflow
 ↓
Save
 ↓
Reload
 ↓
Definition unchanged
```

Run：

```text
Create Run
 ↓
Execute
 ↓
Checkpoint
 ↓
Process Restart
 ↓
Recover
```

---

## 14. Queue Test

测试：

* Job 创建；
* Worker 执行；
* Retry；
* Timeout；
* 并发；
* Job Failure。

---

## 15. Tool Test

File Tool：

```text
Read
Write
```

Shell：

```text
Success
Failure
Timeout
```

Git：

```text
Branch
Diff
Commit
```

HTTP：

```text
GET
POST
Timeout
HTTP Error
Invalid URL
```

---

## 16. Agent Test

Agent 至少测试：

```text
Input
 ↓
LLM Mock
 ↓
Structured Output
```

不要所有测试都真实调用 LLM。

可以使用 Mock Model：

```text
Mock LLM
```

降低：

* 测试成本；
* 测试时间；
* 非确定性。

---

## 17. Coding Agent Test

测试：

```text
Task
 ↓
Coding Agent
 ↓
File Modified
 ↓
Test Passed
 ↓
Git Diff
```

真实 Coding Agent 测试应尽可能在 Sandbox 中执行。

---

## 18. Workflow E2E

完整测试：

```text
Frontend
 ↓
Create Workflow
 ↓
Save
 ↓
Run
 ↓
Backend
 ↓
Runtime
 ↓
Agent
 ↓
State
 ↓
Frontend Monitor
 ↓
Result
```

# Self-Development E2E

## 19. 最终测试

测试真实需求：

```text
Add HTTP Request Node
```

完整流程：

```text
Requirement Analyzer
 ↓
Task Decomposer
 ↓
Coding Agent
 ↓
Test Agent
 ↓
Reviewer
 ↓
Pass?
 ├── Yes → Git Commit
 └── No
      ↓
    Fix Agent
      ↓
    Test
      ↓
    Review
```

---

## 20. 必须证明 Loop

最终 Demo 最好出现：

```text
第一次
→ Test Failed

第二次
→ Fix

第三次
→ Test Passed
```

如果一次成功，也需要通过 Mock 或测试场景证明 Loop 的失败恢复能力。

---

## 21. 手动测试

自动测试之外，必须进行手动验证：

### Workflow Editor

* 创建 Node；
* 连接 Node；
* 修改配置；
* 保存；
* Reload；
* Run。

### Run Monitor

确认：

* Node 状态；
* 当前 Node；
* iteration；
* output；
* error；
* duration。

### Self Development

确认：

* Agent 是否真的修改代码；
* Test 是否真的执行；
* Reviewer 是否真的检查；
* Fix 是否真的修改；
* Git Diff 是否正确；
* Loop 是否真的发生。

---

## 22. Bug 处理流程

发现 Bug：

```text
Reproduce
 ↓
Locate
 ↓
Write / Update Test
 ↓
Fix
 ↓
Run Test
 ↓
Regression Test
```

不要只修表面现象。

---

## 23. 阶段完成标准

一个 Phase 只有在以下条件全部满足后才能标记完成：

```text
□ 功能实现
□ TypeScript Check
□ Lint
□ Unit Test
□ Integration Test（如适用）
□ Manual Test
□ 无已知阻塞性 Bug
□ 文档已更新
□ Git Commit
```

---

## 24. 测试原则

始终优先测试：

```text
核心 Runtime
>
DSL
>
Loop
>
State
>
Agent
>
Tool
>
UI
```

因为 UI Bug 通常容易发现，而 Runtime / State / Loop Bug 会直接影响整个系统的正确性。

---

## 25. 最终原则

不要把测试当成开发结束后的工作。

正确流程是：

```text
设计
 ↓
测试设计
 ↓
实现
 ↓
运行测试
 ↓
修复
 ↓
回归
```

测试必须伴随整个项目开发过程。
