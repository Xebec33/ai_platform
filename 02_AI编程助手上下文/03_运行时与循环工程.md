# 运行时与循环工程

## 1. Runtime 职责

Workflow Runtime 是整个系统的执行核心。

它负责：

* Workflow 初始化；
* Node 调度；
* State 管理；
* Condition；
* Parallel；
* Loop；
* Retry；
* Timeout；
* Error Handling；
* Checkpoint；
* Cancellation；
* Event Streaming。

---

## 2. Runtime 基本流程

```text
Workflow Definition
        ↓
Create Run
        ↓
Load Initial State
        ↓
Execute Node
        ↓
Update State
        ↓
Select Next Node
        ↓
Execute
        ↓
...
        ↓
End
```

---

## 3. Execution State

State 至少包含：

```text
runId
workflowId
status
currentNode
iteration
variables
nodeOutputs
errors
timestamps
```

可以增加：

```text
tokenUsage
latency
toolCalls
agentOutputs
checkpoints
```

---

## 4. Node State Transition

Node 执行过程：

```text
PENDING
  ↓
RUNNING
  ↓
SUCCESS
```

失败：

```text
RUNNING
  ↓
FAILED
```

如果允许 Retry：

```text
FAILED
 ↓
RETRYING
 ↓
RUNNING
```

具体是否将 RETRYING 暴露为持久化状态由实现决定。

---

## 5. Workflow Run 状态

```text
PENDING
RUNNING
PAUSED
SUCCESS
FAILED
CANCELLED
```

状态转换必须有明确规则。

例如：

```text
PENDING → RUNNING
RUNNING → SUCCESS
RUNNING → FAILED
RUNNING → CANCELLED
RUNNING → PAUSED
PAUSED → RUNNING
```

# Loop Engineering

## 6. Loop 的定义

Loop Engineering 是：

> 系统执行任务 → 获取结果 → 观察结果 → 验证结果 → 根据验证结果决定下一步 → 持久化状态 → 再次执行。

不是简单的：

```text
while(true)
```

---

## 7. 标准 Loop

```text
┌─────────────────────────────┐
│                             ↓
Execute → Observe → Verify → Decide
                              │
                     ┌────────┴────────┐
                     ↓                 ↓
                  Continue            Stop
                     │                 │
                     └──────→ End ←────┘
```

---

## 8. Coding Loop

推荐：

```text
Coder
 ↓
Test
 ↓
Reviewer
 ↓
Pass?
 ├── Yes → End
 │
 └── No
       ↓
     Fix
       ↓
     Test
       ↓
   Reviewer
```

---

## 9. Loop 必须具备的能力

### Iteration

记录当前第几次循环。

```text
iteration = 1
iteration = 2
iteration = 3
```

### Max Iterations

例如：

```text
maxIterations = 5
```

超过限制必须停止。

不能允许无限循环。

### Stop Condition

例如：

```text
review.passed == true
```

### Retry

Node 本身可能因为：

* 网络错误；
* LLM API 错误；
* Tool 错误；

需要 Retry。

Retry 与 Loop 是两个不同概念。

```text
Retry：
同一个 Node 再执行一次。

Loop：
完成一轮工作后，根据结果决定是否重新进入工作流程。
```

### Timeout

单 Node 和整个 Workflow 都应考虑 Timeout。

### Cancellation

用户可以手动取消 Run。

### Persistence

Loop 状态必须持久化。

否则进程重启后无法恢复。

---

## 10. Retry 与 Loop 的区别

例如：

```text
Coding Agent
```

调用失败：

```text
Coding Agent
   ↓ error
Retry
   ↓
Coding Agent
```

这是 Retry。

而：

```text
Coder
 ↓
Test
 ↓
Reviewer
 ↓
失败
 ↓
Fix
 ↓
Test
```

这是 Loop。

两者不能混为一谈。

---

## 11. Failure Handling

失败至少分成：

### Node Failure

单个 Node 执行失败。

### Workflow Failure

无法继续执行整个 Workflow。

### Loop Failure

达到：

```text
maxIterations
```

仍然没有满足停止条件。

### Infrastructure Failure

例如：

* Database unavailable；
* Redis unavailable；
* Sandbox crashed；
* LLM timeout。

不同失败类型需要不同处理策略。

---

## 12. Checkpoint

重要状态需要保存：

```text
Workflow Run
↓
Node completed
↓
Checkpoint
```

Checkpoint 可以保存：

```text
currentNode
variables
nodeOutputs
iteration
status
```

这样可以支持：

* Recovery；
* Resume；
* Debug；
* Replay。

---

## 13. Event System

Runtime 应产生事件：

```text
RUN_STARTED
NODE_STARTED
NODE_COMPLETED
NODE_FAILED
LOOP_STARTED
LOOP_ITERATION
LOOP_CONTINUED
LOOP_STOPPED
RUN_COMPLETED
RUN_FAILED
RUN_CANCELLED
```

Frontend 可以通过 SSE 或 WebSocket 接收这些事件。

---

## 14. Runtime 与 LLM 的边界

Runtime：

```text
确定性
```

LLM：

```text
非确定性
```

例如：

### Runtime 决定

```text
iteration >= maxIterations
```

### LLM 决定

```text
这份代码是否需要修改？
```

### Runtime 执行

```text
如果 passed == false → Fix
```

不要让 LLM 通过自然语言直接决定 Runtime 是否跳转。

---

## 15. Loop 测试

必须测试：

### Case 1：第一次失败，第二次成功

```text
Iteration 1
→ Test Failed
→ Fix
→ Iteration 2
→ Test Passed
→ End
```

### Case 2：始终失败

```text
Iteration 1
Iteration 2
Iteration 3
Iteration 4
Iteration 5
→ Max Iterations
→ FAILED
```

### Case 3：Retry

```text
Agent
→ API Error
→ Retry
→ Success
```

### Case 4：Timeout

```text
Agent
→ Timeout
→ Failed / Retry
```

### Case 5：Cancellation

```text
Running
→ User Cancel
→ CANCELLED
```

### Case 6：Recovery

```text
Running
→ Process Crash
→ Restart
→ Load Checkpoint
→ Continue
```

这些测试是 Loop Engineering 的核心验收内容。
