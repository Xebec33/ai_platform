# 自举开发

## 1. 目标

本项目的高级要求是：

> 使用自己开发的 Multi-Agent Workflow Platform，完成平台自身的开发。

即：

```text
Platform
   ↓
Self-Development Workflow
   ↓
Coding Agent
   ↓
Modify Platform Source Code
   ↓
Test
   ↓
Review
   ↓
Fix
   ↓
Commit
```

---

## 2. 自举不是特殊 Runtime

Self Development Workflow 必须运行在普通 Workflow Runtime 上。

不要为了自举再开发第二套 Agent Workflow Engine。

正确架构：

```text
Workflow Platform
       ↓
Workflow Runtime
       ↓
Self Development Workflow
       ↓
Coding / Testing / Review Agents
```

---

## 3. 推荐 Workflow

```text
Requirement Analyzer
        ↓
Task Decomposer
        ↓
┌───────┴────────┐
↓                ↓
Frontend Agent   Backend Agent
└───────┬────────┘
        ↓
    Test Agent
        ↓
  Reviewer Agent
        ↓
      Pass?
     /     \
   Yes      No
    ↓        ↓
 Git       Fix Agent
 Commit       ↓
    ↑──────────┘
```

---

## 4. Requirement Analyzer

输入：

```text
自然语言需求
```

输出结构化需求：

```json
{
  "goal": "...",
  "acceptanceCriteria": [],
  "constraints": [],
  "affectedAreas": []
}
```

---

## 5. Task Decomposer

将需求拆成：

```text
Frontend Task
Backend Task
Test Task
Documentation Task
```

如果任务没有前后端依赖，可以并行。

不能为了“多 Agent”而强行并行。

---

## 6. Coding Agent

Coding Agent：

1. 读取仓库；
2. 读取项目上下文；
3. 理解现有架构；
4. 分析任务；
5. 修改代码；
6. 编写测试；
7. 运行测试；
8. 查看 Git Diff；
9. 返回修改结果。

---

## 7. Test Agent

Test Agent 负责：

* 检查功能；
* 运行测试；
* 分析失败；
* 输出结构化测试结果。

例如：

```json
{
  "passed": false,
  "tests": [
    {
      "name": "HTTP request timeout",
      "passed": false,
      "error": "..."
    }
  ]
}
```

---

## 8. Reviewer Agent

Reviewer 重点检查：

* 功能正确性；
* 架构一致性；
* 类型安全；
* 测试完整性；
* 安全问题；
* 是否存在不必要修改。

输出：

```json
{
  "passed": false,
  "issues": []
}
```

---

## 9. Fix Agent

如果 Review 失败：

```text
Reviewer
 ↓
Issues
 ↓
Fix Agent
 ↓
Modify Code
 ↓
Test
```

重新进入 Loop。

---

## 10. Loop

整个自举开发流程：

```text
Implement
 ↓
Test
 ↓
Review
 ↓
Pass?
 ├── Yes → Commit
 │
 └── No
      ↓
     Fix
      ↓
     Test
      ↓
   Review
```

必须设置：

```text
maxIterations
```

避免 Agent 无限修改代码。

---

## 11. Git Workflow

推荐：

```text
main
 │
 ├── task/xxx
 │
 ↓
Coding Agent
 │
 ↓
Test
 │
 ↓
Review
 │
 ↓
Commit
 │
 ↓
Merge
```

不要让 Coding Agent 一开始直接修改 main。

---

## 12. Sandbox

Coding Agent 应在独立 Sandbox 中：

```text
Docker
 ├── Repository
 ├── Dependencies
 ├── Runtime
 └── Tests
```

需要控制：

* CPU；
* Memory；
* Timeout；
* Network；
* File System。

---

## 13. 第一个自举 Demo

推荐需求：

> 给平台增加 HTTP Request Node，支持 URL、Method、Headers、Body，并能在 Workflow 中运行。

这个任务可以覆盖：

```text
Requirement Analysis
↓
Task Decomposition
↓
Backend Coding
↓
Frontend Coding
↓
Testing
↓
Review
↓
Fix Loop
↓
Git Commit
```

---

## 14. Demo 应该故意制造一次失败

为了证明 Loop Engineering，不应该让第一次就直接成功。

例如：

```text
第一次实现
 ↓
Test Failed
 ↓
Reviewer 发现问题
 ↓
Fix Agent
 ↓
第二次 Test
 ↓
Success
```

这样可以清晰展示：

> 系统不是简单调用几个 Agent，而是具有 Observe → Verify → Decide → Fix → Retry 的闭环能力。

---

## 15. 自举阶段的安全边界

Coding Agent 不允许：

* 删除整个项目；
* 修改 Git 历史；
* 访问宿主机敏感文件；
* 任意访问生产环境；
* 获取真实密钥；
* 修改部署环境；
* 修改核心架构约束而不经过人工确认。

对于高风险操作，需要：

```text
Human Approval
```

---

## 16. Mock 阶段

在真正接入 OpenHands/OpenCode 前，可以先使用 Mock Agent。

例如：

```text
Mock Coder
Mock Tester
Mock Reviewer
Mock Fixer
```

先验证：

```text
Workflow
→ State
→ Loop
→ Retry
→ Persistence
```

全部正确后，再接入真实 Coding Agent。

这样可以降低调试复杂度。

---

## 17. 自举成功标准

必须能够完整展示：

```text
用户提出需求
      ↓
平台分析需求
      ↓
平台拆解任务
      ↓
Coding Agent 修改项目
      ↓
Test Agent 测试
      ↓
Reviewer Agent Review
      ↓
失败
      ↓
Fix Agent 修改
      ↓
重新测试
      ↓
通过
      ↓
Git Commit
```

这才算完成高级要求。
