# 架构与技术栈

## 1. 总体架构

系统采用前后端分离架构。

```text
Browser
   ↓
Vue Frontend
   ↓ HTTP / SSE
Node.js API
   ↓
Workflow Engine
   ↓
LangGraph Runtime
   ↓
Agent / Tool
```

外围基础设施：

```text
                    ┌─────────────┐
                    │ PostgreSQL  │
                    └──────┬──────┘
                           │
Frontend → Backend → Runtime
                           │
                    ┌──────┴──────┐
                    │ Redis       │
                    │ BullMQ      │
                    └──────┬──────┘
                           │
                         Worker
                           │
                     Coding Agent
                           │
                       Sandbox
```

---

## 2. Frontend

### 技术

```text
Vue 3
TypeScript
Vite
Vue Flow
Pinia
```

UI 可以使用：

```text
Element Plus
```

或者：

```text
Naive UI
```

二者选择一个即可。

### Frontend 职责

Frontend 负责：

* Workflow 图形化编辑；
* Node 添加；
* Node 删除；
* Node 配置；
* Edge 创建；
* Workflow 保存；
* Workflow 加载；
* Workflow 运行；
* Run Monitor；
* Node 状态展示；
* 日志和结果展示。

Frontend 不负责：

* Workflow 真正执行；
* Agent 调度；
* Loop 控制；
* 数据库操作；
* Coding Agent 执行。

这些必须由 Backend 负责。

## 4. Workflow 层

Workflow 层是本项目核心。

```text
workflow/
├── dsl/
├── compiler/
├── runtime/
└── nodes/
```

### DSL

负责描述 Workflow。

### Compiler

负责：

```text
Workflow DSL
↓
LangGraph StateGraph
```

### Runtime

负责执行 Workflow。

### Nodes

实现各种具体 Node。

---

## 5. 为什么使用自己的 DSL

前端 Vue Flow 的数据结构不应该直接成为后端 Runtime 的内部结构。

正确流程：

```text
Vue Flow Graph
      ↓
Serializer
      ↓
Workflow DSL
      ↓
Validator
      ↓
Compiler
      ↓
LangGraph
```

这样可以把：

* UI；
* Workflow 定义；
* Runtime；

三个层次解耦。

---

## 6. LangGraph 的职责

LangGraph.js 是底层 Workflow Runtime 基础。

它主要负责：

* Graph；
* State；
* Node；
* Edge；
* Conditional Edge；
* Checkpoint；
* 执行流程。

但项目不能简单变成：

> “把 Vue Flow 数据直接转换成 LangGraph。”

本项目自己的核心能力应该是：

```text
Workflow DSL
+
DSL Validation
+
Workflow Compiler
+
Run Management
+
Loop Engineering
+
Agent / Tool Integration
```

LangGraph 是底层执行引擎，而不是整个产品。

---

## 7. Agent Architecture

Agent 应该抽象成：

```text
AgentConfig
    ↓
AgentExecutor
    ↓
Model Provider
    ↓
LLM
```

建议结构：

```text
agents/
├── agent.ts
├── agent-executor.ts
├── agent-registry.ts
├── model-provider.ts
└── prompts/
```

Agent Executor 应统一处理：

* input；
* prompt；
* model；
* output；
* state；
* error；
* timeout；
* token usage；
* latency。

---

## 8. Tool Architecture

Tool 应采用统一接口。

概念上：

```text
Tool
├── name
├── description
├── inputSchema
├── execute()
└── metadata
```

Tool Registry：

```text
Tool Registry
      ↓
Tool
 ├── File Read
 ├── File Write
 ├── Shell
 ├── Git
 ├── HTTP
 └── Search
```

Agent 不应该直接依赖具体 Tool 实现。

---

## 9. Run Architecture

必须区分：

```text
Workflow Definition
Workflow Run
Execution State
Node Run
Checkpoint
```

例如：

```text
Workflow
    │
    ├── Node A
    ├── Node B
    └── Node C
          │
          ↓
       Run #123
          │
          ├── NodeRun A
          ├── NodeRun B
          └── NodeRun C
```

Run Status：

```text
PENDING
RUNNING
PAUSED
SUCCESS
FAILED
CANCELLED
```

## 11. Queue

使用：

```text
Redis + BullMQ
```

推荐：

```text
API
 ↓
Create Workflow Run
 ↓
BullMQ Job
 ↓
Worker
 ↓
Workflow Runtime
```

这样 API Server 不需要长期阻塞执行 Workflow。

Queue 负责：

* async execution；
* retry；
* concurrency；
* timeout；
* job status。

---

## 12. Coding Agent

Coding Agent 使用 Adapter Pattern。

```text
CodingAgent
      │
      ├── OpenHandsAdapter
      │
      └── OpenCodeAdapter
```

业务层只依赖：

```text
CodingAgent
```

不直接依赖 OpenHands/OpenCode 的内部 API。

这样未来可以替换 Coding Agent。

---

## 13. Sandbox

Coding Agent 不应该直接在 Backend 主机上执行任意代码。

应该：

```text
Coding Agent
      ↓
Docker Sandbox
      ↓
Repository Workspace
```

Sandbox 应控制：

* CPU；
* Memory；
* Timeout；
* Network；
* Workspace；
* Process。

---

## 14. Self Development

Self Development 是普通 Workflow Runtime 的一个应用。

不是第二套 Runtime。

```text
Self Development Workflow
          ↓
Workflow Runtime
          ↓
Agent Nodes
          ↓
Coding Agent
          ↓
Tools
          ↓
Sandbox
```

## 16. 不允许的架构变化

除非用户明确批准，不得：

* 将 Backend 改成 Python；
* 用 Dify Backend 替换 Node Backend；
* 用 LangGraph 取代自己的 DSL；
* 删除 Workflow Runtime；
* 让 Agent Prompt 直接控制整个流程；
* 删除 PostgreSQL 状态持久化；
* 删除 Loop Engine；
* 将 Coding Agent 与核心 Runtime 强耦合；
* 为单个功能进行大规模架构重写。
