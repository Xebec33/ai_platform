# 开源项目参考

## 1. 使用目的

本项目允许参考和复用开源项目代码。

但需要明确：

> **参考开源项目 ≠ 将多个开源项目直接拼接成一个系统。**

AI IDE 应首先理解本项目自身的架构，再根据当前任务选择合适的开源项目进行参考。

本项目的核心能力必须保持自主、清晰：

```text
Workflow DSL
      ↓
DSL Validator
      ↓
Workflow Compiler
      ↓
Workflow Runtime
      ↓
Loop Engineering
      ↓
Agent / Tool
      ↓
Self Development
```

---

# 2. 开源项目总览

当前主要参考：

| 项目        | 主要用途                                      |   优先级 | 使用方式          |
| --------- | ----------------------------------------- | ----: | ------------- |
| LangGraph | Workflow Runtime / State Graph            | ★★★★★ | 直接作为运行时依赖     |
| Dify      | Workflow 产品与可视化设计参考                       | ★★★★☆ | 阅读源码和设计       |
| Paperclip | Agent / Task / Goal / Run / Control Plane | ★★★★☆ | 阅读架构与数据模型     |
| Multica   | Multi-Agent / Coding Workflow             | ★★★☆☆ | 参考 Agent 协作思路 |
| OpenHands | Coding Agent                              | ★★★★★ | 通过 Adapter 接入 |
| OpenCode  | Coding Agent                              | ★★★★★ | 通过 Adapter 接入 |
| Langfuse  | LLM Observability                         | ★★☆☆☆ | 后期可选          |

# 3. LangGraph

## 3.1 定位

LangGraph 是本项目最重要的底层依赖。

主要用于：

* State Graph；
* Node；
* Edge；
* Conditional Edge；
* Workflow Execution；
* Checkpoint；
* Durable Execution。

---

## 3.2 本项目中的位置

推荐：

```text id="z6g0f4"
Vue Flow
    ↓
Own Workflow DSL
    ↓
Validator
    ↓
Compiler
    ↓
LangGraph
    ↓
Runtime
```

LangGraph 是执行基础设施。

---

## 3.3 可以参考

重点阅读：

* StateGraph；
* State；
* Node；
* Edge；
* Conditional Edge；
* Checkpoint；
* Graph Compilation；
* Streaming；
* Persistence。

---

## 3.4 不应该做的事情

不要简单变成：

```text id="gr7s8e"
Vue Flow
 ↓
直接转换成 LangGraph
```

本项目必须拥有自己的：

```text id="5hlk3w"
Workflow DSL
Validator
Compiler
```

这样才能体现平台本身的设计能力。

---

## 3.5 使用方式

正常情况下直接安装 LangGraph.js 依赖：

```text id="h9f4k2"
@langchain/langgraph
```

不需要把 LangGraph 源码复制到项目中。

只有在确实需要研究内部实现时，才阅读其源码。

Dify 主要作为：

> AI Workflow 产品和可视化编排平台的参考。

重点参考：

* Workflow Editor；
* Node Configuration；
* Workflow Variables；
* Node Input / Output；
* Workflow Schema；
* Execution UI；
* Workflow Debugging。

---

## 4.2 可以参考的设计

例如：

```text id="s7yyb8"
Workflow
 ↓
Node
 ↓
Input
 ↓
Output
 ↓
Variable
 ↓
Execution
```

以及：

```text id="8syg0e"
Start
 ↓
LLM / Agent
 ↓
Condition
 ↓
Tool
 ↓
End
```

---

## 4.3 不应该直接使用

本项目 Backend 是：

```text id="jq6wiv"
Node.js + TypeScript
```

因此不应该直接使用 Dify 的 Python Backend 作为本项目 Backend。

不要：

```text id="n5q7zq"
Vue Frontend
+
Dify Backend
+
LangGraph
+
Paperclip
```

这种方式会使项目失去清晰的核心架构。

---

## 4.4 推荐用途

当开发：

* Workflow Editor；
* Node Schema；
* Variable System；
* Workflow UI；

时，可以让 AI IDE 阅读 Dify 对应实现。

# 5. Paperclip

## 5.1 定位

Paperclip 主要作为：

> Agent Organization / Task / Goal / Run / Control Plane 的架构参考。

---

## 5.2 重点参考

重点关注：

```text id="o6egx8"

Task
Goal
Run
```

以及 Agent 如何：

```text id="g0r5bq"

 ↓

 ↓

 ↓
更新状态
```

---

## 5.3 对本项目的帮助

Paperclip 可以帮助设计：

```text id="djh9ym"
Agent
Task
Run
Goal
```

之间的关系。

例如：

```text id="6t5x3h"

 ↓
Task
 ↓
Agent
 ↓
Run
 ↓
Result
```

---

## 5.4 不应该直接复制

Paperclip 的完整产品架构不是本项目必须实现的内容。

当前项目不需要为了参考 Paperclip 而实现：

* 完整组织系统；
* 完整权限系统；
* 企业级管理后台；
* 复杂 Agent 生命周期管理。

只提取对 Multi-Agent Workflow 有价值的设计。

# 7. OpenHands

## 7.1 定位

OpenHands 是本项目重点考虑的 Coding Agent。

它负责：

```text id="0owkbr"
Read Repository
 ↓
Understand Task
 ↓
Modify Code
 ↓
Run Commands
 ↓
Run Tests
 ↓
Inspect Result
```

---

## 7.2 本项目中的位置

OpenHands 不应该直接成为整个 Workflow Runtime。

应该：

```text id="n9syab"
Workflow Runtime
      ↓
Coding Agent Interface
      ↓
OpenHands Adapter
      ↓
OpenHands
      ↓
Sandbox
```

---

## 7.3 Adapter

推荐抽象：

```typescript id="1p0q6w"
interface CodingAgent {
  run(task: CodingTask): Promise<CodingResult>
}
```

然后：

```text id="w2fj3m"
OpenHandsAdapter
```

实现该接口。

这样未来可以替换其他 Coding Agent。

---

# 11. 开源代码使用原则

## 原则 1：优先使用成熟依赖

如果一个能力已经有成熟的 npm package，并且符合项目需求：

```text id="7nbzq7"
优先安装依赖
```

而不是复制源码。

---

## 原则 2：参考源码时先理解

AI IDE 在参考开源项目时，应：

```text id="2o9s2m"
定位相关模块
 ↓
阅读接口
 ↓
理解数据流
 ↓
理解设计原因
 ↓
提取需要的思想
 ↓
实现本项目版本
```

不要直接复制大量无关代码。

---

## 原则 3：核心架构必须属于本项目

以下部分必须保持项目自身的实现：

```text id="8n1r4u"
Workflow DSL
DSL Validator
Workflow Compiler
Workflow Runtime Integration
Loop Engineering
Run / State Management
Self-Development Workflow
```

---

## 原则 4：避免“开源项目拼接”

禁止形成：

```text id="5p8w1g"
Dify UI
+
Dify Backend
+
LangGraph
+
Paperclip
+
Multica
+
OpenHands
```

然后称其为本项目。

正确方式是：

```text id="6gn0h2"
本项目架构
      │
      ├── LangGraph：Runtime 基础
      ├── Dify：Workflow UI / DSL 参考
      ├── Paperclip：Agent / Task 模型参考
      ├── Multica：Multi-Agent 参考
      └── OpenHands：Coding Agent
```

# 16. 最终原则

开源项目的价值在于：

> **站在已有项目的肩膀上，而不是把已有项目拼起来。**

AI IDE 应始终先回答：

```text id="0v9z6x"
本项目需要什么？
        ↓
哪个开源项目已经解决了类似问题？
        ↓
它是如何解决的？
        ↓
哪些设计值得借鉴？
        ↓
哪些代码可以作为依赖？
        ↓
如何保持本项目架构完整？
```

最终目标是：

```text id="0u3y6k"
借鉴开源项目
      ↓
形成自己的架构
      ↓
实现自己的 Workflow DSL
      ↓
实现自己的 Compiler
      ↓
实现自己的 Loop Engineering
      ↓
实现自己的 Self-Development Workflow
```

而不是简单地把多个开源项目组合在一起。
