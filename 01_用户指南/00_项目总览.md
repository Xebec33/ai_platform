# AI Workflow Platform 项目总览

## 1. 项目背景

本项目用于完成腾讯 AI 全栈日常实习面试任务。

面试任务要求：

### 基础要求

实现一套支持多 Agent 编排，并能够完成 Loop Engineering 的 AI 工作流平台。

### 进阶要求

基于该平台，搭建一条能够自举开发平台自身的工作流。

也就是说：

> 平台不仅能够运行 Agent，还应该能够通过 Agent 自动分析需求、拆解任务、修改代码、执行测试、检查结果，并根据测试/Review 结果不断迭代，最终完成对平台自身的开发。

---

## 2. 项目最终目标

最终实现一个具有以下能力的平台：

1. 可视化创建 Workflow
2. 通过节点编排多个 Agent
3. 支持顺序执行
4. 支持条件分支
5. 支持并行执行
6. 支持 Loop Engineering
7. 支持 Workflow 状态持久化
8. 支持 Workflow Run 监控
9. 支持 Agent 调用 Tool
10. 支持 Coding Agent 修改代码
11. 支持 Git 工作区和分支管理
12. 支持沙箱执行代码
13. 支持自动测试
14. 支持 Reviewer Agent
15. 支持失败后自动修复并重新测试
16. 支持通过自身 Workflow 开发平台自身

---

## 3. 最终 Demo

最终至少准备三个 Demo。

### Demo 1：可视化多 Agent Workflow

通过前端拖拽节点构建：

```text
Start
  ↓
Agent A
  ↓
Agent B
  ↓
Condition
 ├── Yes → Agent C
 └── No  → Agent D
  ↓
End
```

展示：

* 节点拖拽
* 节点配置
* 连线
* Workflow 保存
* Workflow 运行
* 节点状态变化
* Agent 输出

---

### Demo 2：Loop Engineering

构建：

```text
Start
  ↓
Coding Agent
  ↓
Test Agent
  ↓
Reviewer
  ↓
Pass?
 ├── Yes → End
 └── No  → Fix Agent
             ↓
            Test
             ↓
          Reviewer
             ↓
            Loop
```

故意让第一次测试失败。

系统应该能够：

1. 发现失败
2. 分析失败原因
3. 让 Coding/Fix Agent 修改代码
4. 再次运行测试
5. 再次 Review
6. 直到通过或者达到最大迭代次数

---

### Demo 3：平台自举开发

给平台提出一个新的开发需求，例如：

> 给 Workflow 平台增加 HTTP Request Node，支持 URL、Method、Headers、Body，并能够在 Workflow 中执行。

然后启动：

```text
需求分析
   ↓
任务拆解
   ↓
┌─────────────────┐
│ Frontend Agent  │
│ Backend Agent   │
└─────────────────┘
   ↓
自动测试
   ↓
Reviewer
   ↓
Pass?
 ├── Yes → Git Commit / Merge → 完成
 └── No  → Fix Agent
              ↓
             Test
              ↓
           Reviewer
              ↓
             Loop
```

整个过程必须由 Workflow Platform 自身执行。

## 6. 最重要的设计原则

### 原则 1：Workflow Definition 与 Workflow Run 分离

Workflow Definition：

> 描述一个 Workflow 是什么。

Workflow Run：

> 描述某一次 Workflow 执行。

Execution State：

> 描述某一次执行当前进行到了什么状态。

三者不能混为一谈。

---

### 原则 2：控制逻辑由 Runtime 负责

不要让 LLM 决定：

* 下一节点是谁
* 是否执行 Loop
* Retry 次数
* Timeout
* 状态持久化

这些属于 Workflow Runtime。

LLM 主要负责：

* 理解任务
* 推理
* 规划
* 代码生成
* 代码修改
* Review
* 业务层面的判断

---

### 原则 3：Loop 必须是真正的工程循环

Loop 不是：

```text
while(true) {
    askLLM();
}
```

而应该包含：

```text
Trigger
  ↓
Load State
  ↓
Execute
  ↓
Observe
  ↓
Verify
  ↓
Decide
  ↓
Continue / Stop
  ↓
Persist State
```

必须考虑：

* iteration
* maxIterations
* stop condition
* retry
* timeout
* failure
* cancellation
* state persistence

---

### 原则 4：不要为了 Demo 过度硬编码

不能写：

```text
if workflowName === "self-development"
    runSpecialWorkflow()
```

自举开发 Workflow 本身必须是普通 Workflow。

平台只是提供：

* Workflow Engine
* Agent
* Tool
* Loop
* State
* Git
* Sandbox

然后通过这些能力组合出“开发平台自身”的 Workflow。

## 9. MVP 原则

不要一开始实现所有节点。

第一版只实现：

```text
Start
Agent
Condition
End
```

之后增加：

```text
Parallel
Loop
Tool
```

最后再增加：

```text
Human Approval
HTTP Request
Code Execution
Git
Shell
File
```

优先保证：

> 少量节点 + 完整运行链路

而不是：

> 大量节点 + 大量 Bug

## 11. 最终项目应该证明什么

这个项目最终不是为了证明：

> 我会调用大模型 API。

而是为了证明：

> 我能够从系统工程角度设计并实现一个 AI Agent Workflow Platform，并理解 Agent、Workflow Runtime、State、Tool、Loop Engineering、Coding Agent、Sandbox、Git 等组件如何协同工作。

重点展示：

```text
AI 能力
+
Workflow 编排
+
工程化 Runtime
+
状态管理
+
自动迭代
+
Coding Agent
+
自举开发
```
