# 开发路线

## 1. 使用方法

整个项目按照 Phase 0 ~ Phase 15 推进。

每个阶段都遵循：

```text
阅读上下文
    ↓
明确本阶段目标
    ↓
AI IDE 分析代码
    ↓
AI IDE 制定实现计划
    ↓
实现
    ↓
TypeScript 检查
    ↓
Lint
    ↓
自动测试
    ↓
人工验证
    ↓
修复问题
    ↓
更新文档
    ↓
Git Commit
```

只有满足本阶段验收标准，才能进入下一阶段。

# Phase 5：Loop Engineering

## 目标

实现本项目最重要的核心能力之一。

## 标准循环

```text
Execute
   ↓
Observe
   ↓
Verify
   ↓
Decide
   ↓
Continue / Stop
   ↓
Persist State
```

## 必须支持

### Iteration

记录当前循环次数。

### Max Iterations

例如：

```text
maxIterations = 5
```

超过后自动失败。

### Stop Condition

例如：

```text
review.passed === true
```

### Retry

节点执行失败时允许重试。

### Timeout

限制单次 Node 和整个 Run 的执行时间。

### Failure Handling

区分：

```text
Node Failure
Workflow Failure
Loop Failure
```

### Cancellation

允许用户手动停止 Run。

### State Persistence

每次重要状态变化都能够保存。

---

## 核心测试

必须实现：

### Case 1：第一次失败，第二次成功

```text
Iteration 1
Test → Failed

Iteration 2
Fix → Test → Passed
```

最终：

```text
SUCCESS
```

### Case 2：永远失败

```text
Iteration 1 → Failed
Iteration 2 → Failed
Iteration 3 → Failed
...
Iteration 5 → Failed
```

最终：

```text
FAILED
```

原因：

```text
MAX_ITERATIONS_REACHED
```

```text

```

Workflow 最后：

```text

 ↓

 ↓

Commit
 ↓

```

## Docker Sandbox

Coding Agent 的代码执行应该尽量放入 Sandbox。

至少考虑：

* Timeout
* CPU Limit
* Memory Limit
* Workspace Isolation
* Network Control

# 每个 Phase 的通用完成规则

一个 Phase 只有同时满足以下条件才算完成：

* [ ] 功能已经实现
* [ ] TypeScript 检查通过
* [ ] Lint 通过
* [ ] 自动测试通过
* [ ] 人工验证通过
* [ ] 没有明显架构问题
* [ ] 文档已经更新
* [ ] Git 已提交

禁止：

> “代码写完了，所以这个 Phase 完成了。”

必须：

> “功能 + 测试 + 人工验证 + 文档 + Git 都完成了。”
