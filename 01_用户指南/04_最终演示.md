# 3. 开场介绍

建议用下面的逻辑介绍。

## 问题

传统 Agent 往往是：

```text
用户
 ↓
LLM
 ↓
答案
```

但复杂任务需要：

```text
Planning
 ↓
Execution
 ↓
Observation
 ↓
Verification
 ↓
Correction
 ↓
Execution
```

因此需要一个能够编排多个 Agent，并管理执行状态和循环的 Workflow Platform。

# 6. Demo 2：Loop Engineering

这是第二个重点 Demo。

---

## Workflow

```text
Start
 ↓
Coding Agent
 ↓
Test
 ↓
Reviewer
 ↓
Passed?
 ├── Yes → End
 └── No → Fix Agent
             ↓
            Test
             ↓
          Reviewer
             ↓
            Loop
```

---

## 演示策略

必须让第一次执行失败。

例如：

```text

```

然后：

```text

```

然后：

```text

修改代码
```

再次：

```text

PASS
```

最终：

```text
SUCCESS
```


### Failure

### Correction

展示 Fix Agent。

### Final Result

最终成功。

# 7. Demo 3：Self-Development

这是整个项目的核心 Demo。

目标：

> 让平台自己开发平台。

---

# 8. Demo Requirement

推荐使用：

> 给平台增加 HTTP Request Node，支持 URL、Method、Headers、Body，并能够在 Workflow 中运行。

这个需求的优点：

* 前端有 Node UI
* Backend 有 Node Runtime
* DSL 有 Node Schema
* Runtime 有 Node Executor
* Tool 有 HTTP Request
* 测试可以验证
* Review 可以检查

因此能够证明平台确实是在开发自己。

# 19. 面试时可以强调的技术点

### 为什么使用 LangGraph？

因为它已经提供：

* State-based execution
* Graph execution
* Conditional routing
* Checkpoint
* Interrupt / Resume

适合作为底层 Runtime。

---

### 为什么自己设计 DSL？

因为：

> Vue Flow 的图结构只是编辑器表示，而 Runtime 不应该直接依赖前端数据结构。

所以：

```text
Vue Flow
 ↓
Project DSL
 ↓
Validator
 ↓
Compiler
 ↓
LangGraph
```

可以实现：

* 前后端解耦
* Workflow 持久化
* Schema Validation
* Versioning
* Runtime Independence

---

### 为什么需要 State？

因为 Agent Workflow 不是一次请求。

它可能：

```text
执行
 ↓
失败
 ↓
修改
 ↓
重新执行
 ↓
继续
```

因此必须保存：

```text
当前节点
循环次数
变量
Node Output
错误
Checkpoint
```

---

### 为什么 Loop 是核心？

因为真实 Agent 系统通常不是：

```text
Input → Output
```

而是：

```text
Goal
 ↓
Plan
 ↓
Act
 ↓
Observe
 ↓
Verify
 ↓
Correct
 ↓
Act
 ↓
...
```

Loop Engineering 是把这种 Agent 行为变成可靠工程系统的关键。

> 一个基于 LangGraph 的可视化 Multi-Agent Workflow Platform，通过自定义 Workflow DSL、状态化 Runtime 和 Loop Engineering 实现复杂 Agent 工作流编排，并进一步通过 Coding Agent、Sandbox 和 Git 构建能够自举开发自身的 AI 软件工程工作流。

# 23. 面试结束时的核心总结

最终希望面试官看到的不是：

> “我做了一个 Agent Demo。”

而是：

> “我实现了一个 AI Workflow Runtime，并把 Multi-Agent、Tool、State、Loop Engineering 和 Coding Agent 组合成了一套能够持续执行、验证和修正的软件工程系统。”

进一步：

> “这套系统不仅能运行普通 AI Workflow，还能够把自身作为开发对象，通过同一个 Workflow Engine 驱动需求分析、任务拆解、代码修改、测试、Review、修复和 Git 提交，实现一定程度的 Self-Development。”
