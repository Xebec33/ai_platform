# 测试与验收

## 1. 核心原则

本项目不能以：

> “代码已经写完”

作为完成标准。

必须满足：

```text
代码实现
+
自动测试
+
人工验证
+
异常测试
+
文档
```

才算完成。

---

# 2. 测试分层

整个项目使用五层测试。

```text
Unit Test
    ↓
Integration Test
    ↓
Workflow Test
    ↓
E2E Test
    ↓
Self-Development E2E
```

---

# 5. Workflow Test

必须建立固定测试 Workflow。

---

## Test 1：最简单 Workflow

```text
Start
 ↓
Agent
 ↓
End
```

预期：

```text
SUCCESS
```

---

## Test 2：Condition

```text
Start
 ↓
Agent
 ↓
Condition
 ├── Yes → Agent A
 └── No  → Agent B
 ↓
End
```

预期：

输入不同：

```text
A → A Branch
B → B Branch
```

---

## Test 3：Parallel

```text
        ┌→ Agent A ─┐
Start ──┤           ├→ End
        └→ Agent B ─┘
```

预期：

Agent A 和 Agent B 均执行成功。

# 6. Loop Test

Loop 是项目最重要的测试之一。

---

## Test 4：一次失败后成功

```text
Agent
 ↓
Test
 ↓
Reviewer
 ↓
Passed?
 ├── Yes → End
 └── No  → Fix
             ↓
            Test
             ↓
          Reviewer
```

第一次：

```text
Test = FAIL
```

第二次：

```text
Test = PASS
```

预期：

```text
Workflow = SUCCESS
iteration = 2
```

---

## Test 5：达到最大迭代次数

设置：

```text
maxIterations = 3
```

每次：

```text
Test = FAIL
```

预期：

```text
iteration = 3
status = FAILED
reason = MAX_ITERATIONS_REACHED
```

---

## Test 6：Node Retry

设置：

```text
maxRetries = 2
```

第一次执行：

```text
ERROR
```

第二次：

```text
SUCCESS
```

预期：

Workflow 最终成功。

---

## Test 7：Timeout

让 Agent 长时间运行。

设置：

```text
timeout = 10s
```

预期：

```text
Node = FAILED
reason = TIMEOUT
```

---

## Test 8：Cancellation

Workflow 执行过程中手动取消。

预期：

```text
Run Status = CANCELLED
```

不能继续执行后续 Node。

---

# 7. State 测试

必须验证：

```text
Workflow State
```

可以正确变化。

例如：

```json
{
  "iteration": 2,
  "currentNode": "reviewer",
  "variables": {},
  "nodeOutputs": {}
}
```

每次 Node 执行完成后：

* State 更新
* Node Output 保存
* Current Node 更新
* Timestamp 更新

---

# 8. Persistence 测试

# 11. Coding Agent 测试

# 13. 人工验收

自动测试通过之后，用户必须自己操作一次。

至少检查：

* UI 是否正常
* Workflow 是否能创建
* Workflow 是否能运行
* Agent 输出是否正常
* Loop 是否真的循环
* 状态是否正确
* 错误是否显示
* Coding Agent 是否修改正确代码
* Git Diff 是否符合预期
* 自举 Workflow 是否真实使用平台 Runtime

---

# 14. 性能不是第一优先级

本项目是面试 Demo。

优先级：

```text
正确性
>
稳定性
>
可解释性
>
架构合理性
>
性能
```

不要为了追求性能过早加入复杂优化。

---

# 15. 发现 Bug 后的处理方式

不要直接继续开发新功能。

应该：

```text
发现 Bug
 ↓
复现
 ↓
定位
 ↓
写测试
 ↓
修复
 ↓
运行相关测试
 ↓
运行完整测试
 ↓
人工验证
```

如果 Bug 属于架构问题：

> 先暂停当前开发，重新评估架构。

---

# 16. Phase 完成标准

一个 Phase 必须满足：

* [ ] 功能实现
* [ ] Unit Test
* [ ] Integration Test（如适用）
* [ ] Workflow Test（如适用）
* [ ] E2E Test（如适用）
* [ ] 人工验证
* [ ] 文档更新
* [ ] Git Commit

否则：

> Phase 不算完成。
